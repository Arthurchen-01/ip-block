操作

关于「引导到隧道」：EgressGuard 做不到把一条已经建立的连接改道进隧道 —— 那条连接显式绑定了物理网卡，根本不进 TUN，用户态没有 API 能把它转进去。
真正有效的引导是两件事：①掐断 → 逼它重连（重连时不显式绑网卡就会走 TUN）； ②把系统代理指向隧道端口（浏览器等读系统代理的程序会主动走隧道）。
隔离粒度默认是「程序→目标」而不是「程序」—— 因为 python.exe / java.exe / svchost.exe 这类共用宿主一个 exe 承载无数程序，按程序封杀会让一个脚本裸奔连坐掉所有同类程序。

能真正"导回 VPN 出口"的只有一件事：删掉让它绕过隧道的路由。 实测（tests/exp_guide_to_tunnel.py）：删掉那条指向物理网卡的主机路由后， 按路由表走的程序重连时源地址会变成 198.18.x.x —— 进了隧道。
但对显式绑定物理网卡的程序，删路由也没用（实测源地址不变）， 那种只能掐断。你机器上绕过隧道的连接基本都是后者。
